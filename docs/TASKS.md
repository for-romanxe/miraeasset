**석규 시작 가이드**

첫날: README대로 클론·세팅 후 `.venv/bin/python eval/run_eval.py`에서 105/105 확인.

문항 추가는 `eval/build_evalset.py`의 `MANUAL` 리스트에 기존 형식을 복사해
질문·기대 문서(`expect.docs`)만 바꾸면 된다. 소재 3종:
1. `parser/out/docs/doc29.md` FAQ 표의 '유사질문표현' — 같은 질문의 다른 말투
2. `parser/out/INDEX.md`에서 문서마다 "이 문서를 찾아야 답할 수 있는 질문" 1~2개
3. 함정: 틀린 전제("세액공제 2,000만원까지 되죠?"), 자료 밖 질문

추가 후 `run_eval.py -v`로 실패 문항을 본다. 실패 원인이 고객 말투 ↔ 문서 용어
차이면 `agent/pipeline/retriever.py`의 `QUERY_EXPAND`에 동의어 쌍을 추가한다.
PR 완료 기준: 문항 N개 추가 + 전체 통과율 유지·상승.

**승빈 시작 가이드**

첫날: 세팅 후 `agent/pipeline/calculator.py`의 기존 계산기 3개
(세액공제·연금소득세·퇴직세감면) 구조 파악.

계산기 확장 우선순위와 규칙 원문 위치:
1. 연금수령한도 — 공식이 `parser/out/docs/doc39.md`에 있음
2. 중도인출 세금 — 기타소득세 16.5% + 예외 사유 (doc20, doc46~50)
3. 종합과세 비교 — 1,500만원 초과 시 종합 vs 16.5% 분리 (doc38)
4. ISA 전환 혜택 — 전환금 10% 추가 공제, 300만원 한도 (doc23)

각 함수는 기존 형식대로 `(결과, 계산과정 문자열, 근거 doc번호)`를 반환.
규칙은 반드시 원문 문서에서 확인하고 구현 (기억·인터넷 금지).
함수 하나마다 평가셋 검증 문항 1개 추가 (석규와 협업).

가드레일은 `agent/pipeline/router.py`의 `OUT_OF_SCOPE`·`UNSAFE` 패턴 —
석규의 함정 문항이 시험대다. 8/6 전에 라우터용 HCX 분류 프롬프트
(질문 → 유형·나이·금액·계좌유형 JSON 추출 지시문) 초안을 미리 써두면
연동 당일 바로 붙일 수 있다.
