## 🟠 P1 — 키 수령 직후 ~ 8월 중순 (핵심 기능)

### 연성 (연결·설명 담당)
1. **HCX 실연동** — `agent/llm.py` 교체 지점에 키 연결, 프롬프트 다듬기, 5개 참고 질의로 답변 품질 1차 확인
2. **⚠️ Verifier(self-check)** — 답변의 수치·주장이 retrieved_context에 실제로 있는지 HCX로 재검증, 없으면 삭제/한계고지로 교체. 발표 기준 "검증 실패 = 금융권 최악 실패 유형(23.5%)"
3. 답변 출처 표기 포맷 통일 ("근거: doc41(제목) p2" — 모든 답변 필수 규정)

### 승빈 (판단·계산 담당)
1. **세제 계산기 4종** (순서대로): 연금수령한도(doc39) → 중도인출 세금(doc20·46~50) → 종합과세 비교(doc38) → ISA 전환 공제(doc23). 규칙은 반드시 원문 확인, 함수마다 검증 문항 1개 추가
2. **라우터 HCX 전환** — 슬롯 스키마는 발표의 **Target/Action/Condition** 방식, 판단 축은 **Cost(룰로 끝낼 수 있나)/Intent/Context/Risk/Ambiguity 5축** (BRIEFING 23~24장). 키 오기 전엔 분류 프롬프트 초안 작성
3. **Assume+Expose 경로** — 조건 1개만 빈 질의는 역질문 대신 "△△ 기준으로 답변드리며, 다르면 알려주세요"로 가정 명시 후 답변 (역질문 남발 방지)

### 석규 (자료·시험 담당)
1. **깨뜨리는 문항 만들기** — 105/105는 문항이 아직 쉽다는 뜻. 구어체·오타("공제 얼마까지 되나여"), 복합 질의(제도+세제+절차), 유도성 전제, 애매한 표현("돈 좀 빼고 싶은데요") 추가. 문항 5~10개 + 실패 분석이 한 PR 단위
2. 실패 원인이 어휘 갭이면 `QUERY_EXPAND` 동의어 보강
3. 문서 원문 숙독하며 "고객이 오해할 만한 지점" 수집 (함정 문항·기술제안서 재료)
