# 차별화 아이디어 (팀 논의용)

평가지표에 직결되는 **방어형**과 점수를 더 따는 **공격형**으로 구분.

## 방어형 — 감점을 막는다

### 1. 역질문 상태머신 (조건부 추천 엔진)
"좋은 상품 추천해주세요" 류 질의에서 계좌유형·투자기간·위험성향 슬롯이
채워질 때까지 확인 질문을 던지고, 채워진 조합별로 결론 제공.
평가지표의 "단정 추천 금지 + 역질문"을 프롬프트가 아닌 코드 분기로 보장.
참고 질의 5개 중 1개가 정확히 이 유형.

### 2. 세제 계산기 모듈 (LLM 계산 금지)
세액공제 한도(연금저축 600 + IRP 합산 900), 연금소득세율(나이·수령연차별),
퇴직소득세 정산, 종합과세 문턱(1,500만원)을 파이썬 함수로.
LLM은 질의에서 나이·소득·금액만 추출. 계산 과정은 think_trace에 수식으로 노출
→ 수치 정확성 + 추론 논리성 동시 대응.

### 3. 답변 후 근거 대조 self-check
생성된 답변의 각 수치·주장이 retrieved_context에 실제로 있는지 HCX로 재검증,
근거 없는 문장은 삭제 또는 한계 고지로 교체. 환각 지표의 보험이자
"데이터에 없는 걸 묻는 함정 문제" 방어막.

### 4. 잘못된 전제 교정기
"세금 감면이 어마어마하다던데" 같은 유도성 질문에서 전제를 추출 →
근거와 대조 → 틀리면 바로잡고 시작. 평가지표에 명시된 항목이며
참고 질의 '상' 난이도가 이 함정.

## 공격형 — 점수를 더 딴다

### 5. 펀드 시리즈 자동 비교 테이블
funds.json 펀드명 정규화로 같은 시리즈(솔로몬 단기/중장기/장기) 자동 감지,
6축 비교표 + 차이 요약 생성. 유사상품 추천은 asset_type_group + 위험등급 ±1 이웃.

### 6. 자체 평가셋 + 회귀 테스트 하네스
doc29(디폴트옵션 FAQ 100선: 질문-유사표현-표준답변-근거ID 완비)를 시드로
난이도×유형 매트릭스 150~200문항 제작, 자동 채점.
예선 6주간 "고치면 점수가 오르는지"를 매일 확인할 수 있는 인프라 = 최대 차별화.

### 7. think_trace를 채점자용으로 설계
평가자가 읽는 필드임을 역이용. `[라우팅] → [도구] → [검색] → [검증]`
구조화 로그로 과정을 보여주면 정성평가(기술완성도·논리성)에서 유리.

## 우선순위

1~2주차에 **2번(계산기)과 6번(평가셋)** 먼저 — 2번은 정답률 상한을 올리고
6번은 나머지 전부를 측정 가능하게 만든다. 1·3·4번은 뼈대에 분기점만 미리 설계,
5·7번은 마무리 카드.
